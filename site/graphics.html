자동 촬영 도구

오류 창 A를 닫은 뒤 나타난 B가 남아, 이전 오류와 새 실행 결과가 혼재하고 Codex의 대응이 반복되는 문제가 있었습니다. 사용자는 일정 간격으로 재확인하고, 오류 창이 없음을 확인한 뒤 다음 작업을 진행하도록 제안했습니다. Codex는 오류 창 정리와 결과 판별 코드를 보완했습니다. 자동 촬영 도구의 초기 정리 코드에도 종료 후 재조회와 잔존 시 실패 반환이 있었습니다. 보완 대상은 후속 창의 반복 정리와 같은 창 잔존·새 창 출현의 구분, 안정 대기 후 최종 검사였습니다.

  • 자료 성격: 공개 영상은 현상과 대응 절차를 설명하는 재현 시연입니다.
  • 검증 방법: 테스트 창 5개 조건을 각 3회 확인했습니다. 해당 재검증은 테스트 창을 이용한 정리 코드의 정상·실패 조건 확인입니다.
  • 결과 해석: 실패 감지 조건의 충족은 오류 창 정리 성공을 의미하지 않습니다. 지연 오류는 감지 후 실패 종료하고 자동 재정리하지 않습니다.

이 정리 실행의 종료 코드 0은 잔존 오류 없음, 3은 잔존 오류 감지·실패 보고입니다. 지연 발생·종료 거부 조건의 3/3은 실패를 제대로 감지했다는 뜻이며 오류 제거 성공이 아닙니다. 호출자가 반환 코드를 확인하고 다음 작업을 중단하는지는 별도 확인 대상입니다.

후속 창은 일정 간격으로 확인하며 정리합니다. 같은 창이 남거나 정리 후 안정 대기에서 오류가 다시 감지되면 실패 코드를 반환합니다. 안정 대기 중 감지된 오류는 자동 재정리하지 않습니다.

  • 별도 회귀 테스트: 완료 대기 한도 5초의 원본이 실패하고 한도만 15초로 늘린 사본이 통과했으나, 실패 원인은 확정하지 못했습니다.
  • 확인하지 않은 범위: 실제 DLL 복구·Clean/Rebuild·원래 촬영 재개를 검증한 결과로 표현하지 않습니다.

Assimp 구조 호환

Pivot 보존으로 생성되는 보조 노드와 애니메이션 채널 구조가 기존 로더의 처리 방식과 맞지 않아 캐릭터 형태가 무너지는 사례입니다. 동일한 자산과 Assimp 버전에서 옵션 적용 전후의 구조와 보행 결과를 비교합니다.

당시 기록과 후속 검증 구분

  • 당시 확인: 당시 수정 결과는 본인이 직접 실행해 확인했습니다.
  • 재현 비교 조건: 별도 재현 사본에서 Codex가 초기 자세 보완을 양쪽에 동일하게 적용하고 Pivot 옵션을 바꿔 수행했습니다.
  • 원본 반영 여부: 초기 자세 보완은 원본에 반영하지 않았습니다.
  • 확인 범위: 구조 검사는 5개 클립·실제 재생 비교는 보행 클립에 한정합니다.
  • 미검증 범위: 다른 클립 전체 재생·장시간 실행·임의 자산은 미검증입니다.

화면 좌표를 선택 광선으로 바꾸고 구 표면의 드래그 입력으로 회전을 적용했습니다. Virtual Trackball 예제의 선택 지점과 회전 누적 과정을 기존 자료로 설명합니다.

  1. 화면 입력·광선
  2. 구 교차 판정
  3. 방향 차이·쿼터니언
  4. 모델 회전 누적
구현 범위·검증 조건과 한계

VirtualTrackball의 경계 구 선택과 쿼터니언 회전 누적을 설명합니다. 노란 점은 선택 지점이며, 연속 조작은 기존 시연에서 확인합니다.

GPU ID 피킹이나 삼각형 표면의 정밀 교차로 설명하지 않습니다. 원본 Earth·cubemap 에셋은 비공개 실행 의존성입니다.

별도 예제 · CPU 광선 피킹

화면 좌표를 inverse view-projection으로 역변환해 near/far 지점에서 광선을 만듭니다. CPU에서 경계 구 교차를 검사하고 누르기·이동·해제에 따라 hit marker를 갱신합니다. 누른 상태라도 구체 실루엣을 벗어나면 marker가 사라집니다.

Step3은 _Solution 기반의 교재 학습 예제이며 독자 설계한 선택 시스템으로 주장하지 않습니다. GPU object ID readback과 VirtualTrackball의 쿼터니언 회전은 각각 별도 예제입니다.

스켈레탈 애니메이션

클립의 본 변환을 계층에 따라 갱신하고 GPU에서 가중합으로 정점을 변형했습니다. 기존 동일 클립의 재생 결과와 CPU 갱신·GPU 스키닝의 연결을 설명합니다.

기존 클립 재생 자료이며 Assimp 재현 검증의 기여와 구분합니다.

  1. 클립·본 계층
  2. CPU 변환 갱신
  3. GPU 버퍼 전달
  4. 정점 가중합
구현 범위·검증 조건과 한계

클립의 본 변환을 부모·자식 계층에 따라 갱신해 GPU 버퍼로 전달합니다. 본 인덱스·가중치로 정점의 위치·법선·접선을 변형합니다.

현재 활성 경로는 state=2에서 frameCount를 증가시키는 반복 재생입니다. 상태 전환·블렌딩·프레임률 독립 애니메이션 시스템의 완성을 의미하지 않습니다.

FBX 호환 검증은 5개 클립의 구조 검사와 보행 클립의 실제 재생에 한정합니다. 별도 재현 사본 양쪽에 같은 초기 자세 보완을 적용하고 Pivot 옵션만 비교했으며, 초기 자세 보완은 원본에 미반영입니다. 당시 수정과 이후 재현 검증의 기여를 구분합니다.

GPU 연기

Compute Shader로 3차원 속도·밀도 필드를 갱신하고 밀도 텍스처를 렌더링했습니다. 기존 영상의 연기 형태 변화와 속도를 이용한 밀도 이송 연산을 설명합니다.

  1. 속도·밀도 필드
  2. 압력·속도 보정
  3. 밀도 이송
  4. Ray Marching
구현 범위·검증 조건과 한계

Compute Shader로 3차원 속도·밀도장을 갱신하고, 이송·부력 계산에서 볼륨 레이 마칭 출력까지 연결합니다.

동일 시연의 4.025초·22.808초 프레임을 비교합니다. 선택 프레임이 전체 움직임·안정성을 대신하지 않으며 물리 정확도나 통제된 성능 측정 자료가 아닙니다.

유한한 레이 마칭 단계와 밀도·조명 설정에 따라 시각 결과가 달라집니다.
